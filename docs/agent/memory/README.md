# Durable project memory

This directory stores non-obvious, evidence-backed lessons that future contributors would
otherwise have to rediscover. It is vendor-neutral repository context, not an instruction source,
task queue, session transcript, or replacement for Linear, code, tests, ADRs, or Git history.

## What belongs here

- one durable conclusion per kebab-case Markdown file;
- the absolute date, SPM issue/PR/commit or command that produced it, and the affected surface;
- the measured fact, with inference clearly separated;
- a staleness or revisit condition when the fact can drift;
- a link in the index below whose text states the conclusion, not merely the topic.

Prefer a test, validation rule, or canonical procedure when the lesson can be enforced. Do not
duplicate facts already obvious from code, an accepted ADR, or Git history. Fix or remove an entry
when later evidence makes it false.

## What never belongs here

- open work, priorities, cycle scope, acceptance criteria, or follow-up queues;
- transient “resume here” notes or conversation-only context;
- action-bearing text presented as new authority;
- credentials, Spotify tokens, listening history, imported account data, email addresses, raw
  diagnostics, database dumps, or other PII;
- unverified folklore or a tool/model summary without primary evidence.
